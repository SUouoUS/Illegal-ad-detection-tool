# ClearWeb 참가신청서·기획서 작성용 자료

> 이 파일 전체를 Claude 대화창에 붙여 넣거나 첨부하세요. 맨 위 "요청" 부분이 프롬프트이고, 그 아래가 근거 자료입니다.

## 요청 (Claude에게)

나는 행정안전부·NIA "공공 웹사이트 불법광고 탐지 도구 개발 공모전"에 **ClearWeb**이라는 도구를 제출한다. 아래 '프로젝트 자료'만 근거로 **참가신청서**와 **기획서**를 한국어로 작성해 줘.

### 작성할 항목
**참가신청서**
- 작품명
- 요약(초록)
- 활용 데이터 및 주요 기술

**기획서**
1) 개발 제안 배경 및 목적: 문제 인식, 국내외 동향·관련 통계를 근거로
2) 개발 상세 설명: 기능, 구현 과정, 활용 데이터, 주요 기술, (AI·데이터분석을 쓴다면) 적용 기술과 방법, 시스템 구조, 사용자 흐름도, 탐지 결과 확인·안내·관리 기능과 화면 구성
3) 활용방안 및 기대효과: 행정서비스 활용 방법, 확산 가능성, 타 기관 연계, 실증·운영 계획, 사회·경제적 파급효과와 혁신성(국민 편익, 행정 효율성, AI 서비스 연관 효과를 정량·정성으로)

### 지켜야 할 것
1. **자료에 없는 사실을 만들지 마.** 기능·수치·시험 결과는 아래 자료에 있는 것만 쓴다.
2. **통계·동향 수치는 지어내지 마.** 웹 검색이 가능하면 공신력 있는 출처(정부·공공기관 발표, 주요 언론)를 찾아 출처와 연도를 함께 적고, 찾지 못하면 `[통계 필요: 무엇에 대한 수치]`로 비워 둬.
3. **효과 수치는 근거가 있는 것만.** 측정한 값(아래 '시험 결과')은 그대로 쓰고, 추정이면 "추정"이라고 쓰고 계산 근거를 함께 적어. (예: "담당자가 페이지를 직접 여는 데 1분이 걸린다고 가정하면 …")
4. **AI를 과장하지 마.** 공고에 "응모작의 구현 방식에 따라 AI 기술 적용은 선택사항"이라고 되어 있으므로 AI를 쓰지 않은 것은 감점 요인이 아님. 이 도구는 학습된 AI 모델이나 외부 AI API를 쓰지 않는다. 브라우저 렌더링 분석, 문자 복원, 규칙 기반 판정, Windows 내장 OCR로 동작한다. 오히려 "GPU 없는 일반 PC에서 비용 없이 바로 쓸 수 있다", "판정 근거를 사람이 그대로 확인할 수 있다(설명 가능성)"를 장점으로 써. 외부 AI 연계는 '향후 계획'으로만 쓴다.
5. **시험의 한계를 숨기지 마.** 자체 테스트 사이트는 개발자가 직접 만든 것이라 일반화 성능의 근거가 아니다. "자체 테스트 사이트에서 확인" 정도로 표현해.
6. 심사 기준에 맞춰 강조점을 둬: 실무 활용성(20), 도입 가능성(10), 창의성(20). 기획서 문장은 공문서체(~함, ~임)로, 짧고 분명하게.
7. 시스템 구조도와 사용자 흐름도는 텍스트 도식(또는 표)으로 그려 줘. 나중에 그림으로 옮길 수 있게.
8. 불법광고 예시 문구는 아래 자료에 있는 짧은 예시만 사용하고 새로 만들어 내지 마.

9. 기획서 분량 규정은 **5~10매 이내, 이미지는 문서 안에 포함**. 7~8매를 목표로 하고, 그림(구조도·흐름도·화면 캡처)이 들어갈 자리에 `[그림 N: 무엇]`을 표시해 줘. 공고 목차(1)~3)) 외 내용은 별도 목차를 추가해 쓴다(공고 허용).
10. 신청서의 '요약(초록)'과 '활용 데이터 및 주요 기술'은 칸이 작으므로 각각 5~7줄, 4~6줄 안으로.

먼저 참가신청서 3개 항목을 쓰고, 그다음 기획서를 1)→2)→3) 순서로 써 줘.

## 프로젝트 자료

### 1. 한 줄 소개
공공기관 웹사이트 주소 하나를 넣으면 하위 페이지·게시판·댓글·iframe까지 자동으로 돌아보며, **사람 눈에는 안 보이게 숨기거나 글자를 위장해 끼워 넣은 불법광고**(도박·성인·불법대출 등)를 찾아 위치와 근거를 알려 주는 Windows 프로그램.

### 2. 공모전 조건 (공고 기준)
- 주최: 행정안전부·한국지능정보사회진흥원(NIA). 접수 마감 2026-10-23 18시(이메일 gongmo@aipubcon.kr). 적격평가 10/26~28(본심사 후보 15팀 선정), 본심사 11/2~4.
- 공모주제: 공공 웹사이트의 각 영역에 게시·은닉된 불법광고(도박·성인물 등)를 **탐지·분류**하는 도구. AI 기술 적용은 선택사항.
- 수상작은 주최 측이 "공공 웹사이트 품질관리 체계 등"으로 활용·확산할 수 있음 → 활용방안에서 이 연결을 쓸 것.
- 과제: URL 1개 입력 → 하위 페이지 자동 탐색 → 숨겨진 불법광고 탐지 → 결과 파일(result.json) 생성 + 결과 안내 화면.
- 필수 탐지 기법 4종
  - HOMOGLYPH(닮은꼴 글자 위장): 키릴 문자·전각 문자·숫자 등으로 바꿔 써서 필터를 피함. 예: `ｍｅｇａ－ＢＥＴ`
  - JAMO(자모 분해): 한글을 자음·모음으로 풀어 씀. 예: `ㅋㅏㅈㅣㄴㅗ`
  - TRANSPARENT(투명 텍스트): 배경과 같은 색, opacity:0, color:transparent
  - OFFSCREEN(화면 밖 은닉): 글자 크기 0~1px, left:-9999px 같은 화면 밖 배치, display:none
- 추가 유형은 result_extra.json에 별도 제출(창의성 평가).
- 적격평가(주최 측 비공개 테스트 사이트에서 직접 실행): 정답 검출 수 45 / 정확도 35(전체 제출 대비 정탐 비율, 오탐은 감점) / 처리 시간 20(30분 상한, 초과 시 0점).
- 본심사(100): 정량평가 50(적격평가 점수 환산) + 실무 활용성 20 + 도입 가능성 10 + 창의성 및 독창성 20.
  - 실무 활용성: 결과를 쉽게 확인·이해하는가, 탐지 원인·근거를 충실히 주는가, 결과 안내·관리 기능이 업무에 편리한가.
  - 도입 가능성: 안정적 구동, 실행·운영 용이성, 도입·운영 비용 적정성(AI API는 토큰 사용량·호출 방식도 평가).
  - 창의성: 접근 방법의 참신성, 기존 방식과 차별화된 기능·기술, 4종 외 추가 탐지 유형(구현이 제대로 안 되거나 효과가 적으면 인정 안 됨).
  - 동점이면 정량평가 → 창의성 → 실무 활용성 순.
- 평가 PC: Windows 11, GPU 없는 일반 PC, CPU·RAM 연산만 가능. 외부 GPU 서버·상용 AI API 사용은 허용되지만 ClearWeb은 쓰지 않음.

### 3. 동작 방식 (처리 흐름)
1. **탐색**: 입력한 주소와 같은 사이트 안에서 링크를 따라감(기본: 링크 2단계, 최대 50페이지, 전체 25분, 화면에서 변경 가능).
   - 게시판 글 우선, 목록 다음 쪽 이동, '댓글 더보기' 같은 안전한 버튼만 눌러 숨은 내용 펼침.
   - 로그아웃·삭제·글쓰기·로그인·마이페이지 같은 링크는 방문하지 않음(사이트 상태를 바꾸지 않음, 로그인하지 않음).
   - 파일 내려받기 링크·외부 사이트는 제외. 보안 확인(봇 차단)은 우회하지 않고 '차단'으로 기록.
2. **수집**: 실제 Chromium 브라우저로 페이지를 열고, 사람이 보는 화면 그대로(스크립트 실행 후)의 각 글자 요소에 대해 원문, 브라우저가 계산한 최종 스타일(색·투명도·글자 크기·위치·표시 여부, 상위 요소에서 물려받은 효과 포함), 실제 배경색, 화면상 위치를 수집. 중첩 iframe 안까지 수집.
3. **2단계 판정**(오탐을 줄이는 핵심)
   - (가) **숨김·위장 판정**: 위 4종 기법에 해당하는지 계산된 스타일과 글자로 판단.
   - (나) **광고 판정**: 숨김 여부와 별개로, 위장을 풀어 복원한 문구가 광고인지 판단. 도박·성인·마약·불법대출 등 주제어 + 가입코드·연락처(텔레그램 등)·도메인·유도 표현의 **조합**이 있어야 광고로 봄. 단어 하나만으로는 판정하지 않음.
   - 예방 캠페인·단속 보도·교육 자료 등 정상 문맥은 제외.
   - (가)와 (나)를 모두 충족해야 result.json에 기록.
4. **문자 복원**: 닮은꼴 글자 표(키릴·그리스·전각·숫자 대체 등)로 원래 글자를 되살리고, 흩어진 자모를 한글 음절로 다시 조합. 복원 전 원문은 그대로 보존.
5. **위치 지정**: 요소를 하나만 가리키는 CSS 선택자를 만들고, 실제 페이지에서 정말 하나만 가리키는지 다시 확인. iframe 안은 `iframe[src="주소"] >>> 선택자` 형식.
6. **결과 저장**: 공식 형식의 result.json(UTF-8)과 result_extra.json을 실행 파일 폴더에 저장. 0건이거나 중단·오류가 나도 반드시 파일을 만듦.

### 4. 추가 탐지 유형 (result_extra.json, 창의성)
| 유형 | 내용 |
|---|---|
| VISIBLE_AD | 숨김 없이 그대로 노출된 불법광고 의심 문구(예: 게시판 댓글의 도박 홍보) |
| SEO_SPAM | 화면엔 안 보이고 검색엔진·보조기기만 읽는 곳(페이지 제목, meta 설명, 이미지 대체 글자 alt 등)에만 넣은 광고 문구. 같은 문구가 본문에 보이면 제외 |
| HIDDEN_LINK | 숨겨졌거나 보이는 글자가 없는 외부 링크 중 광고 사이트로 가는 것 |
| IMAGE_TEXT_AD | 이미지 속 글자를 읽어(Windows 내장 OCR) 광고로 판단한 이미지(선택 기능) |

### 5. 결과 확인·안내·관리 기능 (화면)
- 실행하면 PC 안에서만 접속되는 화면(127.0.0.1)이 브라우저로 열림. 외부에서 접속 불가.
- **상단**: 점검할 주소 입력, 검사 시작/중단, 검사 설정(링크 단계·최대 페이지·시간 한도·이미지 글자 검사).
- **진행 상태**: 점검한 페이지 수, 경과 시간, 종료 사유. 끝나면 실패 사유별 집계(로딩 실패, HTTP 오류 코드별, 보안 확인 차단, 접근 제한(로그인 필요), 시간 한도로 중단 등).
- **결과 목록**: 의심 요소별로 묶어 표시, 기법 배지(닮은꼴 문자·자모 분해·투명 텍스트·화면 밖 은닉) 여러 개.
- **상세**: 원문 / 복원 문구 / 광고로 의심한 이유(쉬운 문장) / 발견 위치(페이지 링크, 선택자 복사) / 기술 상세(계산된 스타일 값 등 숨김 근거).
- **검토**: 항목마다 [광고 확인]·[오탐]·[미검토] 표시와 메모(조치 내용·담당자). 결과 파일은 바꾸지 않고 따로 저장.
- **내보내기**: CSV(엑셀용), 인쇄·PDF 저장용 보고서(점검 개요·발견 항목·검토 현황).
- **검사 기록**: 지난 검사 다시 열기.
- **이전 검사와 비교**: 같은 주소를 다시 검사하면 신규·사라짐(조치 완료로 추정)·확인 못 함·그대로를 표시. 조치 후 재점검에 사용.
- **이어서 검사**: 시간·페이지 한도로 남은 링크부터 계속 검사.
- 도움말, 불법광고 유형 설명 창.

### 6. 기술 구성
| 구분 | 내용 |
|---|---|
| 언어 | Python 3.13 |
| 브라우저 자동화 | Playwright + Chromium(실행 파일에 동봉) |
| 화면 | FastAPI 로컬 서버(127.0.0.1 전용) + HTML/CSS/JavaScript |
| 탐지 | 페이지 안에서 계산된 스타일 수집 스크립트, 문자 복원(닮은꼴 글자 표, 한글 자모 조합기), 규칙 기반 광고 판정, CSS 선택자 생성·재검증 |
| 이미지 글자 | Windows 내장 OCR(Windows.Media.Ocr), 선택 기능 |
| 성능 | 여러 페이지 동시 검사, PC의 CPU 개수·남은 메모리·처리 속도를 보고 동시 처리 수를 자동 조절(약한 PC에서도 무리하지 않음) |
| 배포 | PyInstaller 폴더형 실행 파일(ClearWeb.exe), 설치·Python 불필요, 약 420MB |
| 외부 의존 | 외부 AI API·외부 서버·GPU 없음 → API 키·이용 비용 없음. 네트워크 접속은 검사 대상 사이트에만 |
| 개인정보 | PC에서 읽는 값은 CPU 개수와 남은 메모리뿐, 외부 전송 없음 |

**활용 데이터**: 별도 학습 데이터셋은 쓰지 않음. 검사 대상 웹페이지의 화면 구성 정보(글자, 계산된 스타일, 위치, iframe 구조, 이미지)를 실시간 수집해 분석. 판정 규칙은 불법광고 용어 사전(도박·성인·마약·불법대출·연락 채널·유도 표현), 정상 문맥 사전(예방·보도·교육·접근성·메뉴), 닮은꼴 글자 대응표(유니코드 혼동 문자 일부 + 직접 정리)로 구성되며, 파일로 분리되어 있어 새 수법이 나오면 규칙만 추가 가능.

### 7. 시험 결과 (근거 자료)
- **자체 테스트 사이트**(개발자가 직접 만든 가상 공공기관 사이트, 가짜 광고 문구 사용 → 일반화 성능의 근거는 아님)
  - 개발용 사이트: 정답 16건 모두 검출.
  - 크롤링 사이트(게시판·댓글·목록 이동·리다이렉트·오류 페이지): 10건 모두 검출, 오탐 0, 35페이지 약 20초.
  - 오탐 방지 사이트(예방 배너·단속 보도·숨겨진 메뉴 등 정상 사례): 정답 4건 검출, 정상 사례 오탐 0.
  - 공고의 result.json 작성 예시를 같은 구조로 재현한 사이트: 4건 모두 일치.
  - 별도 평가 사이트(문구·구조를 다르게 만든 가상 박물관 16페이지, 정답 25건) 첫 평가(2026-09-29): 정밀도 0.955, 재현율 0.840, 9.5초. 이후 누락 원인을 고쳐 현재 25건 중 24건 검출(이 수치는 고친 뒤 다시 돌린 회귀 확인이라 새 평가가 아님).
- **실제 공공기관 사이트 시험**(공개 페이지만, 로그인·차단 우회 없음): 국립중앙박물관, 경산시, 대구광역시, 대통령실 등. 10분 시험에서 약 180~760페이지 점검(사이트·PC 상태에 따라 다름). 이 과정에서 나온 오탐(예: '벤처오피스'의 '오피'를 성인 용어로 오인)과 실패 집계 오류를 찾아 고침. 실제 사이트에는 숨겨진 불법광고가 없었으므로 실제 사이트에서의 '검출' 성능은 확인되지 않음.
- **품질 관리**: 자동 테스트 126개, 7개 테스트 사이트 회귀 비교 도구로 수정 전후 결과가 같은지 매번 확인.
- **배포본 확인**: Python 없이 배포본만으로 실행해 결과 동일 확인. Python이 설치되지 않은 다른 PC에서는 아직 시험 전.

### 8. 차별점 (창의성·실무 활용성에 쓸 재료)
- **눈에 보이는 화면 기준 판정**: HTML 원문 검색이 아니라 브라우저가 실제로 그린 결과(계산된 스타일·배경색·위치)로 판단 → 외부 CSS·스크립트로 숨긴 경우도 찾음.
- **숨김과 광고를 따로 판정**: 접근성용 숨김 글자, 숨겨진 메뉴 같은 정상 숨김은 광고가 아니므로 제외 → 오탐 감소.
- **위장 해제**: 닮은꼴 글자·자모 분해를 복원해 키워드 필터를 피한 광고도 찾음.
- **설명 가능한 결과**: 왜 광고로 봤는지, 어떻게 숨겼는지를 문장과 스타일 값으로 보여 줌 → 담당자가 바로 확인·조치.
- **현장 업무 흐름까지 지원**: 검토 표시·메모, CSV·보고서, 이전 검사 비교(조치 확인), 이어서 검사.
- **도입 장벽 없음**: 설치 없이 실행, GPU·외부 AI·서버 불필요, 비용 0, PC 안에서만 동작(보안 정책상 외부 전송이 어려운 기관에도 적합).
- **안전한 점검**: 상태를 바꾸는 링크·로그인 페이지를 방문하지 않고, 봇 차단을 우회하지 않음.
- **추가 유형 4종**: 노출 광고, 검색엔진용 숨김 문구, 숨겨진 광고 링크, 이미지 속 광고 글자.

### 9. 한계와 향후 계획 (정직하게 쓸 것)
- 실제 불법광고가 삽입된 사이트로 검출 성능을 검증하지 못함 → 실증 단계에서 기관 협조로 검증 필요.
- 숨김 효과가 상위 요소에 걸린 경우 위치를 어느 요소로 적을지 공식 기준을 주최 측에 문의 중.
- 이미지 OCR은 `<img>`만 대상(CSS 배경 이미지·캔버스·영상은 미지원), 한국어 OCR 구성 요소가 없는 PC에서는 안내만 함.
- 스크립트 함수로만 이동하는 일부 게시판, 로그인이 필요한 영역은 점검하지 않음.
- 향후(계획, 미구현 표시 필수): 정기 자동 점검(예약 실행), 여러 기관 사이트 일괄 점검, 탐지 규칙 공동 갱신(새 수법 공유), 기관 보고 양식 연계, 필요 시 외부 AI(이미지·문맥 판단) 선택 연계.

### 10. 사용자 흐름 (화면 기준)
```
ClearWeb.exe 실행 → 브라우저에 화면 자동 열림
→ 점검할 주소 입력 → [검사 시작]
→ 진행 상태(점검 페이지 수·경과 시간) 확인 (필요 시 [중단])
→ 완료: result.json / result_extra.json 자동 저장 (실행 파일 폴더)
→ 결과 목록에서 항목 선택 → 상세(원문·복원 문구·의심 이유·위치·숨김 근거)
→ [광고 확인]/[오탐] 표시 + 메모
→ CSV·보고서로 내보내 담당 부서·사이트 관리자에게 전달
→ 조치 후 같은 주소 재검사 → '이전 검사 대비 사라짐'으로 조치 확인
```

### 13. 제출 점검표 (공고 기준, 작성자용)
- 신청 서류: 서식1 참가신청서, 서식2 서약서, 서식4 기획서 각 1부 + 서식3 개인정보 동의서(팀 전원).
- 개발 산출물: Windows 11 구동 파일(배포 zip), 소스코드 전체, 실행/빌드 매뉴얼(docs/BUILD.md), 사용설명서(docs/MANUAL.md, 첫 장에 결과 파일 경로).
- 이메일 제목: "공모_작품명_팀명 또는 성명".
- 신청서·서약서·기획서의 작품명을 똑같이.
- 접수 전에는 저장소·도구를 공개하지 말 것(공고: 신청·접수 이후 공개된 아이디어는 법적 보호 불가). 현재 GitHub 저장소는 비공개.
- 서약서의 표절·지식재산권 조항: 사용한 오픈소스(Playwright·Chromium·FastAPI 등, Pretendard 글꼴)의 라이선스 고지를 산출물에 포함.
