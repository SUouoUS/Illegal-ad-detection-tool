# 주최 측 확인 요청 — location 기준

## 질문
숨김 스타일이 **광고 문구만 담은 상위 요소**에 적용되어 있을 때, `location`으로 어느 요소를 기재해야 정답으로 인정되는지 확인 부탁드립니다.

```html
<div class="post-body">
  <p>시스템 점검으로 예약이 일시 중단됩니다.</p>
  <div class="legacy" style="display:none">
    <p>(광고 문구)</p>
  </div>
</div>
```

1. 이 경우 정답 `location`은 다음 중 무엇입니까?
   - (가) 숨김 스타일이 적용된 상위 요소: `div.post-body > div.legacy`
   - (나) 광고 문구를 담은 요소: `div.legacy > p`
   - (다) 둘 다 정답으로 인정
2. 같은 원칙이 `opacity:0`, `color:transparent`, `font-size:0`, 화면 밖 배치(`position:absolute; left:-9999px`)처럼 상위 요소에 적용된 다른 은닉 기법에도 똑같이 적용됩니까?
3. 상위 요소 안에 광고 문구 요소가 여러 개(예: `<p>` 두 개가 합쳐서 광고 한 건) 있을 때는 상위 요소 1건으로 기재합니까, 문구 요소마다 기재합니까?

## 배경
- 모집요강 붙임4는 `location`을 "웹페이지에서 불법광고가 검출된 요소의 위치"로 정의하고, 예시 `div.notice-board > span.visually-hidden`을 듭니다. 예시는 숨김이 적용된 요소와 문구를 담은 요소가 같아서 위 경우를 구분하지 못합니다.
- 같은 광고를 상위·하위 두 건으로 모두 제출하면 한 건은 오탐이 되므로, 기준을 확인한 뒤 한 가지로 기재하려 합니다.

## 현재 도구의 처리(확인 전 가정)
- (가)를 사용: 숨김 스타일을 가진 상위 요소가 광고 문구만 담고 있으면 그 상위 요소를 기재(`docs/SPEC_NOTES.md` 가정 2). 상위 요소에 다른 내용이 섞여 있으면 광고 문구를 담은 최소 요소를 기재.
- 자체 평가 사이트(`testsites/eval`)의 정답은 공식 문장("검출된 요소") 기준으로 (나)를 사용해 두었으며, 이 차이로 누락 1건·오탐 1건이 발생함. 답변을 받기 전에는 어느 쪽도 점수에 맞춰 바꾸지 않음.

# 주최 측 확인 요청 — 평가 PC 환경과 처리 시간 측정

## 질문
1. 공고에 안내된 내용(Windows 11, GPU 없는 일반 PC, CPU·RAM 연산만 가능) 외에 CPU 코어 수, 메모리 용량, 실제 PC인지 가상 PC인지, 인터넷 회선 대략 속도를 알려 주실 수 있습니까?
2. 평가 중 같은 PC에서 다른 프로그램(다른 참가 도구 포함)이 동시에 실행됩니까?
3. 처리 시간은 "URL 입력, 탐지 시작 → 탐지 완료"로 안내되어 있습니다. 30분 안에 끝나지 않으면 그때까지의 결과 파일로 평가합니까, 아니면 시간 초과로 처리합니까?

## 배경
- 도구는 여러 페이지를 동시에 열어 검사합니다. 동시에 여는 수가 많을수록 빠르지만 메모리와 CPU를 더 씁니다. 평가 PC 사양을 모르면 약한 PC에서 무리하지 않도록 보수적으로 정해야 합니다.
- 현재는 PC의 CPU 코어 수·남은 메모리·검사 중 처리 시간을 보고 동시 처리 수를 스스로 조절하는 방식을 검토하고 있습니다(개인을 알아볼 수 있는 정보는 조회하지 않으며 외부로 보내지 않음).

# 주최 측 확인 요청 — 서명 없는 실행 파일과 보안 경고

## 질문
1. 제출하는 Windows 실행 파일에 코드 서명(게시자 인증서)이 필요합니까? 서명이 없으면 내려받은 zip을 풀어 처음 실행할 때 Windows SmartScreen 경고("Windows의 PC 보호")가 표시됩니다. 평가 시 이 경고에서 '추가 정보 → 실행'으로 진행해 주시는 것이 허용됩니까?
2. 평가 PC에 Windows Defender 외의 백신이나 실행 제한 정책(허용된 프로그램만 실행 등)이 적용되어 있습니까? 적용되어 있다면 제출물을 예외로 등록해 실행하는 절차가 있습니까?

## 배경
- 실행 파일은 PyInstaller로 만든 폴더형 배포본(Chromium 브라우저 포함)이며, 이 방식의 실행 파일은 서명이 없을 때 SmartScreen 경고가 뜨고, 일부 백신이 의심 파일로 잘못 잡는 경우가 알려져 있습니다(개발 PC의 Windows Defender에서는 문제 없음).
- 사용설명서 첫 부분에 경고 해제 방법(zip '차단 해제' 또는 '추가 정보 → 실행')을 안내해 두었습니다.

# 주최 측 확인 요청 — result.json의 meta.topic 값

## 질문
1. `meta.topic`에는 어떤 값을 넣어야 합니까? 공고의 예시처럼 글자 그대로 `"TOPIC"`을 넣으면 됩니까, 아니면 정해진 다른 값(대회명, 팀명, 과제 번호 등)이 있습니까?

## 배경
- 공고의 result.json 예시에는 `"topic": "TOPIC"`으로만 적혀 있고 설명이 없습니다. 자리 표시용 예시인지, 실제로 그 글자를 넣으라는 뜻인지 알 수 없습니다.
- 채점(정답 검출·정확도)은 findings로 하므로 점수에는 영향이 없을 것으로 보지만, 결과 파일 형식 검사에서 값이 다르다고 처리될까 확인을 요청합니다.

## 현재 도구의 처리(확인 전 가정)
- 공고 예시 그대로 `"TOPIC"`을 넣습니다. 답변을 받으면 `clearweb/result_writer.py`의 `TOPIC` 한 곳만 바꾸면 됩니다.
