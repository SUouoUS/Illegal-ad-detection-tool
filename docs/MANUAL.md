# ClearWeb 사용설명서

## 결과 파일 위치 (먼저 확인)
| 파일 | 위치 | 생성 조건 |
|---|---|---|
| `result.json` (적격평가용, 필수 4종) | 프로그램 폴더(개발 환경에서는 저장소 최상위 폴더) | 검사가 끝날 때마다 항상. 탐지 0건·중단·페이지 로딩 실패여도 생성 |
| `result_extra.json` (추가 탐지: 이미지 속 글자) | `result.json`과 같은 폴더 | '이미지 속 글자 검사'를 켜고 OCR이 실제로 실행된 경우에만 |
| 검사 기록(화면용) | `runs/<검사시각>/scan.json`, 이미지 미리보기 `runs/<검사시각>/images/` | 검사마다 |

환경 변수 `CLEARWEB_RESULT_DIR`로 결과 폴더를 바꿀 수 있습니다.
※ 이미지 검사를 끈 채 검사하면 `result_extra.json`은 새로 쓰지 않습니다. 같은 폴더에 이전 파일이 있으면 그대로 남으므로 제출 전에 확인하세요.

## 실행 전: Windows 보안 경고(파란 창)
ClearWeb.exe에는 코드 서명(게시자 인증서)이 없어서, 인터넷에서 받은 zip을 풀어 처음 실행하면 Windows가 "Windows의 PC 보호" 파란 창(SmartScreen)을 띄울 수 있습니다. 바이러스가 발견됐다는 뜻이 아니라, 서명과 다운로드 이력이 없는 프로그램이라는 안내입니다. 둘 중 한 가지 방법을 쓰세요.

- **방법 1 (권장, 압축 풀기 전)**: 받은 zip 파일을 마우스 오른쪽 단추로 누르고 **속성** → 아래쪽 **보안: '차단 해제'** 에 체크 → **확인**. 그다음 압축을 풀면 경고가 뜨지 않습니다.
- **방법 2 (경고가 이미 떴을 때)**: 파란 창의 **추가 정보** → **실행**을 누릅니다. 같은 PC에서는 다시 묻지 않습니다.

기관 보안 정책으로 실행이 막히거나 백신이 파일을 격리하면, 그 PC의 관리자에게 이 폴더를 예외로 허용해 달라고 요청해야 합니다(이 프로그램은 검사 대상 사이트 외에는 접속하지 않고, 결과는 실행 파일 폴더에만 저장합니다).

## 실행 (배포본, Windows 11)
1. 받은 zip을 원하는 폴더에 풉니다(위의 '차단 해제'를 먼저 하면 편합니다). Python이나 다른 프로그램을 따로 설치할 필요가 없습니다.
2. `ClearWeb\ClearWeb.exe`를 더블클릭합니다. 검은 콘솔 창에 화면 주소가 표시되고, 기본 브라우저에 점검 화면(`http://127.0.0.1:8765/`, 사용 중이면 다음 번호)이 열립니다.
3. 콘솔 창을 닫으면 프로그램이 종료됩니다.
- 화면 없이 실행: `ClearWeb.exe scan <주소> [--max-depth 2] [--max-pages 50] [--budget 1500] [--no-follow] [--ocr]`
- 결과 파일은 `ClearWeb.exe`가 있는 폴더에 생깁니다(위 표).

## 실행 (개발 환경)
```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python -m clearweb
```
배포본을 만드는 방법은 `docs/BUILD.md`를 참고하세요.

## 화면 사용 순서
1. '점검할 웹 주소'에 주소를 넣고 '검사 시작'. 필요하면 '검사 설정'에서 링크를 따라가는 횟수·최대 페이지 수·시간 한도·이미지 속 글자 검사를 바꿉니다.
2. 상태줄에서 진행(점검 페이지 수, 대기, 경과 시간)을 확인합니다. 실패나 한도 도달은 강조 표시됩니다.
   - '최대 페이지 수'는 방문 시도 수입니다. 점검 + 실패 + '이미 점검한 페이지로 이동'(다른 주소가 이미 본 페이지로 연결된 경우)을 합한 값이 한도가 됩니다.
   - 프레임의 '점검 중 사라짐'은 페이지가 점검 도중 프레임을 지운 경우로, 실패가 아닙니다.
   - '불러오지 못한 페이지'는 로딩 실패·시간 초과·주소 이름 해석 실패·보안 확인 차단·사이트 알림창 뒤 빈 화면(로그인·권한 필요 등)입니다. 'HTTP 응답 오류'는 서버가 오류 상태 코드(400·404·500 등)로 답한 경우로 따로 표시하며, 종료 사유에 종류별·코드별 수가 나옵니다. '접근 제한'은 사이트가 로그인·권한 필요 등의 알림창을 띄운 뒤 빈 화면으로 보낸 페이지로, 실패와 따로 셉니다(로그인은 하지 않음. 주소에 mypage·login 같은 계정 전용 단어가 있는 링크는 처음부터 방문하지 않음). '시간 한도로 중단'은 전체 시간 한도가 끝나 마지막에 다 점검하지 못한 페이지로, 실패에 넣지 않고 '이어서 검사'에서 다시 점검합니다. 링크가 로그인 페이지로 넘어가면 '접근 제한 — 로그인 페이지로 이동됨'으로 표시합니다. '일부만 로딩'은 로딩이 제한 시간을 넘었지만 그때까지 받은 내용으로 점검한 페이지로, 실패에 넣지 않습니다. 저장된 기록은 `http://127.0.0.1:<포트>/?run=<검사 기록 ID>`로 다시 열 수 있습니다. 열면 파일 내려받기가 시작되는 링크는 '파일 링크'로 기록하며 실패나 페이지 수에 넣지 않습니다.
3. '탐지 결과'에서 항목을 선택하면 오른쪽에 원문·복원 문구·광고로 의심한 이유·발견 위치가 나옵니다. '기술 상세'에 판단 근거, 실제로 일치한 문자열과 그 위치(원문/복원문 기준 몇 번째 글자), 선택자가 있습니다. 숨긴 부분이 더 큰 광고 문구의 일부이면 '판정 범위: 숨긴 부분이 속한 상위 문구 전체'로 표시됩니다.
3-1. 시간·페이지 한도나 중단으로 방문하지 못한 링크가 남으면 상태줄에 **'이어서 검사'** 버튼이 나타납니다. '검사 상세'의 '검사한 범위'에 점검한 페이지 수, 마지막으로 점검한 페이지, 남은 링크 수가 표시됩니다. 버튼을 누르면 남은 링크부터 계속 검사하며(이미 점검한 페이지는 다시 방문하지 않음), 결과 화면과 `result.json`에는 이전 검사 결과까지 합쳐서 나옵니다. 이어서 하는 검사에는 그때의 '검사 설정'(최대 페이지 수·시간 한도)이 적용됩니다. 화면 없이: `ClearWeb.exe scan --resume <검사 기록 ID>`(runs 폴더 이름).
   - **동시 처리**: 여러 페이지를 동시에 열어 검사합니다. 기본값 '자동'은 논리 프로세서 수로 최대치를 정하고(4개 이하: 4, 5~8개: 6, 9개 이상: 8), 남은 메모리로 메모리 제한을 정해 보통 4페이지로 시작합니다(메모리가 적으면 2). 검사 중에도 메모리를 다시 확인해, 다른 프로그램을 닫아 메모리가 생기면 상한을 올리고(두 번 연속 확인 후, 실제 동시 처리는 1분마다 한 단계씩), 메모리가 부족해지면 바로 줄입니다(1GB 미만이면 몇 초 안에). 메모리가 충분해도 늘렸을 때 처리 속도가 떨어지거나 시간 초과가 늘면 늘리지 않습니다. 줄일 때 진행 중인 페이지는 끊지 않고 새 페이지 시작만 미룹니다. 문제가 있으면 2·4·6·8 중 하나로 고정할 수 있습니다(화면 없이: `--concurrency 4`). '검사 상세'의 '동시 처리'에 바뀐 과정과 이유가 표시됩니다.
   - 자동 조절을 위해 확인하는 것은 **논리 프로세서 개수와 남은 메모리 양뿐**입니다. 컴퓨터 이름·사용자 이름·일련번호 등은 조회하지 않고, 확인한 값은 PC 밖으로 보내지 않으며 검사 기록(scan.json)에만 남깁니다.
   - '전체 시간 한도'는 최대 180분까지 정할 수 있습니다. 공모전 평가의 처리 시간 한도는 30분이므로 제출용 검사는 29분 이하로 두세요.
4. 이미지 검사를 켰다면 목록 아래 '이미지 속 글자'에 광고 의심·불확실 이미지가, '이미지 처리 내역'에 모든 이미지의 처리 결과와 실패·건너뜀 사유가 나옵니다.

## 이미지 속 글자 검사 (선택, 기본 꺼짐)
- 범위: 검사가 **방문한 페이지**(진입 페이지와 하위 페이지)의 `<img>` 요소. 각 페이지에 삽입된 프레임(iframe, 중첩 포함) 안의 `<img>`도 포함하며, 위치는 `iframe[src="…"] >>> 선택자` 형식으로 기록합니다. 이미지만을 위해 사이트를 따로 다시 탐색하지 않습니다.
- 어떤 이미지를 읽는가: 브라우저가 실제로 고른 이미지(currentSrc)를 먼저 읽습니다. 지연 로딩 이미지는 `data-src` 등의 속성에서 주소를 찾습니다. `srcset`에 더 큰 후보가 있고 먼저 읽은 이미지에서 의심 근거가 없으면 큰 후보를 한 번 더 확인합니다.
- 검사하지 않는 것: CSS 배경 이미지, canvas, 동영상·애니메이션의 두 번째 이후 프레임, SVG, blob 주소, `<picture>`의 `<source>` 후보, 광고 네트워크가 내보내는 광고(요청을 차단함), 방문하지 않은 페이지의 이미지, 보안 확인(봇 차단)으로 본문을 받지 못한 페이지의 이미지. 그림 자체의 의미(선정성 등)는 판단하지 않고 **이미지 속 글자만** 읽습니다.
- 엔진: Windows 내장 OCR(Windows.Media.Ocr, 한국어 인식기). 외부 서버나 AI API를 쓰지 않고, 실행 중 모델을 내려받지 않습니다.
- 한국어 OCR 구성 요소가 없으면 화면에 '사용할 수 없음'과 설치 방법이 표시됩니다. 설치: 설정 > 시간 및 언어 > 언어 및 지역 > 한국어 > 언어 옵션 > '광학 문자 인식', 또는 관리자 PowerShell에서
  `Add-WindowsCapability -Online -Name "Language.OCR~~~ko-KR~0.0.1.0"`
- 판정: 이미지 한 장 안의 **한 문구 영역**만으로 광고 기준을 충족하면 '광고 의심', 근거가 부족하면 '불확실', 그 밖은 '해당 없음'. 내려받기·해석 실패, 한도 초과, 중단은 '실패/건너뜀/시간 초과/중단'으로 따로 기록하며 '광고 없음'으로 취급하지 않습니다. 이미지 결과는 확정 판정이 아니며, OCR 추출문은 원문이 아닙니다.
- 제출 파일: '광고 의심'만 `result_extra.json`에 `technique: "ETC"`, `extra_finding: "IMAGE_TEXT_AD(이미지 속 광고 의심 문구)"`로 기록합니다. `result.json`에는 넣지 않습니다.
- 같은 이미지(내용이 같은 파일)는 OCR 결과를 재사용하고, 발견된 페이지와 요소 위치는 각각 기록합니다.
- 기본 한도: 페이지당 이미지 40장, 검사 전체 300장(서로 다른 이미지 파일 기준. 이미 처리한 파일이 다른 페이지에 다시 나오면 결과를 재사용하고 한도에 세지 않음), 파일 8MB, 4천만 화소, 긴 변 2400px 초과 시 축소, 700px 미만은 2배 확대, 내려받기 8초, 이미지 검사 전체 120초. 한도·중단·전체 시간 예산에 걸린 이미지는 '이미지 처리 내역'과 '검사 상세'에 사유와 함께 표시됩니다.
- 실제 수집 범위 확인: '검사 상세'의 '이미지·OCR' 줄을 보세요. 이미지 수는 img 요소 수이고 괄호에 서로 다른 파일 수가 나옵니다. '글자 인식 완료'는 내려받기와 OCR 처리가 끝난 이미지 수(글자가 없어도 포함)이고, 괄호의 '글자가 나온 이미지'가 실제로 글자를 읽은 수입니다. '건너뜀'은 사유별(전체 개수 한도, 페이지당 개수 한도, 시간 한도, 아이콘 크기, 지원하지 않는 형식, 파일 크기 한도)로 나뉩니다.
- 알려진 한계: 자모를 분해한 글자와 전각 영문 이미지는 안정적인 인식을 보장하지 못합니다. OCR 오독(예: 'AI' 누락, '볼'→'불')이 있을 수 있으며, 현재 OCR 엔진과 시도한 전처리에서는 해결되지 않았습니다.
