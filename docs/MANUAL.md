# ClearWeb 사용설명서

## 결과 파일 위치 (먼저 확인)
| 파일 | 위치 | 생성 조건 |
|---|---|---|
| `result.json` (적격평가용, 필수 4종) | 프로그램 폴더(개발 환경에서는 저장소 최상위 폴더) | 검사가 끝날 때마다 항상. 탐지 0건·중단·페이지 로딩 실패여도 생성 |
| `result_extra.json` (추가 탐지: 이미지 속 글자) | `result.json`과 같은 폴더 | '이미지 속 글자 검사'를 켜고 OCR이 실제로 실행된 경우에만 |
| 검사 기록(화면용) | `runs/<검사시각>/scan.json`, 이미지 미리보기 `runs/<검사시각>/images/` | 검사마다 |

환경 변수 `CLEARWEB_RESULT_DIR`로 결과 폴더를 바꿀 수 있습니다.
※ 이미지 검사를 끈 채 검사하면 `result_extra.json`은 새로 쓰지 않습니다. 같은 폴더에 이전 파일이 있으면 그대로 남으므로 제출 전에 확인하세요.

## 실행 (배포본, Windows 11)
1. 받은 zip을 원하는 폴더에 풉니다. Python이나 다른 프로그램을 따로 설치할 필요가 없습니다.
2. `ClearWeb\ClearWeb.exe`를 더블클릭합니다. 검은 콘솔 창에 화면 주소가 표시되고, 기본 브라우저에 점검 화면(`http://127.0.0.1:8765/`, 사용 중이면 다음 번호)이 열립니다.
3. 콘솔 창을 닫으면 프로그램이 종료됩니다.
- 화면 없이 실행: `ClearWeb.exe scan <주소> [--max-depth 2] [--max-pages 50] [--budget 1500] [--no-follow] [--ocr]`
- 결과 파일은 `ClearWeb.exe`가 있는 폴더에 생깁니다(위 표).

## 실행 (개발 환경)
```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python -m clearweb
```
배포본을 만드는 방법은 `docs/BUILD.md`를 참고하세요.

## 화면 사용 순서
1. '점검할 웹 주소'에 주소를 넣고 '검사 시작'. 필요하면 '검사 설정'에서 깊이·최대 페이지 수·시간 한도·이미지 속 글자 검사를 바꿉니다.
2. 상태줄에서 진행(점검 페이지 수, 대기, 경과 시간)을 확인합니다. 실패나 한도 도달은 강조 표시됩니다.
3. '탐지 결과'에서 항목을 선택하면 오른쪽에 원문·복원 문구·광고로 의심한 이유·발견 위치가 나옵니다. '기술 상세'에 판단 근거와 선택자가 있습니다.
4. 이미지 검사를 켰다면 목록 아래 '이미지 속 글자'에 광고 의심·불확실 이미지가, '이미지 처리 내역'에 모든 이미지의 처리 결과와 실패·건너뜀 사유가 나옵니다.

## 이미지 속 글자 검사 (선택, 기본 꺼짐)
- 범위: 검사가 **방문한 페이지**(진입 페이지와 하위 페이지)의 `<img>` 요소. 각 페이지에 삽입된 프레임(iframe, 중첩 포함) 안의 `<img>`도 포함하며, 위치는 `iframe[src="…"] >>> 선택자` 형식으로 기록합니다. 이미지만을 위해 사이트를 따로 다시 탐색하지 않습니다.
- 어떤 이미지를 읽는가: 브라우저가 실제로 고른 이미지(currentSrc)를 먼저 읽습니다. 지연 로딩 이미지는 `data-src` 등의 속성에서 주소를 찾습니다. `srcset`에 더 큰 후보가 있고 먼저 읽은 이미지에서 의심 근거가 없으면 큰 후보를 한 번 더 확인합니다.
- 검사하지 않는 것: CSS 배경 이미지, canvas, 동영상·애니메이션의 두 번째 이후 프레임, SVG, blob 주소, `<picture>`의 `<source>` 후보, 광고 네트워크가 내보내는 광고(요청을 차단함), 방문하지 않은 페이지의 이미지, 보안 확인(봇 차단)으로 본문을 받지 못한 페이지의 이미지. 그림 자체의 의미(선정성 등)는 판단하지 않고 **이미지 속 글자만** 읽습니다.
- 엔진: Windows 내장 OCR(Windows.Media.Ocr, 한국어 인식기). 외부 서버나 AI API를 쓰지 않고, 실행 중 모델을 내려받지 않습니다.
- 한국어 OCR 구성 요소가 없으면 화면에 '사용할 수 없음'과 설치 방법이 표시됩니다. 설치: 설정 > 시간 및 언어 > 언어 및 지역 > 한국어 > 언어 옵션 > '광학 문자 인식', 또는 관리자 PowerShell에서
  `Add-WindowsCapability -Online -Name "Language.OCR~~~ko-KR~0.0.1.0"`
- 판정: 이미지 한 장 안의 **한 문구 영역**만으로 광고 기준을 충족하면 '광고 의심', 근거가 부족하면 '불확실', 그 밖은 '해당 없음'. 내려받기·해석 실패, 한도 초과, 중단은 '실패/건너뜀/시간 초과/중단'으로 따로 기록하며 '광고 없음'으로 취급하지 않습니다. 이미지 결과는 확정 판정이 아니며, OCR 추출문은 원문이 아닙니다.
- 제출 파일: '광고 의심'만 `result_extra.json`에 `technique: "ETC"`, `extra_finding: "IMAGE_TEXT_AD(이미지 속 광고 의심 문구)"`로 기록합니다. `result.json`에는 넣지 않습니다.
- 같은 이미지(내용이 같은 파일)는 OCR 결과를 재사용하고, 발견된 페이지와 요소 위치는 각각 기록합니다.
- 기본 한도: 페이지당 이미지 40장, 검사 전체 300장, 파일 8MB, 4천만 화소, 긴 변 2400px 초과 시 축소, 700px 미만은 2배 확대, 내려받기 8초, 이미지 검사 전체 120초. 한도·중단·전체 시간 예산에 걸린 이미지는 '이미지 처리 내역'과 '검사 상세'에 사유와 함께 표시됩니다.
- 실제 수집 범위 확인: '검사 상세'의 '이미지·OCR' 줄(이미지 수, 수집한 페이지 수, 성공·실패·한도, 수집하지 못한 페이지 수)을 보세요.
- 알려진 한계: 자모를 분해한 글자와 전각 영문 이미지는 안정적인 인식을 보장하지 못합니다. OCR 오독(예: 'AI' 누락, '볼'→'불')이 있을 수 있으며, 현재 OCR 엔진과 시도한 전처리에서는 해결되지 않았습니다.
