
## 크롤러 범위·속도 개선 (2026-09-28)
대형 사이트(디시인사이드 게시글 URL 1개)에서 대기 페이지가 수백 개로 늘어나는 문제 대응. 탐지 규칙·result.json 형식은 변경 없음.
- 기본값: 최대 깊이 2, 최대 50페이지, 같은 형태 주소 10개, 전체 25분. 화면 '검사 설정'과 CLI(--max-depth, --max-pages, --budget)에서 변경.
- 우선순위 큐: 얕은 페이지 → 본문(main/article/table 등) 링크 → 진입 경로 공유 → 앞쪽 목록 페이지 순. 최대 페이지 수는 방문 시점에 적용(먼저 발견된 링크가 자리를 차지하지 않음).
- 제외: 로그인·회원가입·검색·글쓰기·수정·답글·추천·신고·내려받기·인쇄·공유 등(검사 가치 낮은 링크), 기존 상태 변경 링크·파일·외부 링크.
- 같은 형태 주소: 경로의 숫자 구간을 일반화하고 쿼리 이름으로 묶어 형태별 10개. 목록의 다음 쪽 이동은 깊이를 늘리지 않음.
- 쿼리: 추적 파라미터(utm_*, fbclid, gclid 등)만 제거. 같은 글에 추가 파라미터가 붙은 주소는 뒤로 미룸(버리지 않음).
- 차단: 이미지·폰트·영상·ping/beacon + 광고·분석 네트워크(Google·Meta·네이버·카카오 광고·통계 등, scanner.BLOCK_HOSTS).
- 대기: domcontentloaded 후 load 최대 3초, network idle 최대 1초, DOM 안정 0.5초(최대 2초). '더보기' 후 대기 0.8초.
- 분석(파이썬)을 별도 스레드로 옮기고 반복 계산 제거: 결과 동일(저장한 11개 프레임 비교), 페이지당 약 1.0초 → 0.2초.
- 화면: '대기 N개'는 실제 검사 예정 수(남은 한도 이내), '페이지 수 한도로 제외 N개'를 따로 표시.

## 숨겨진 뉴스 목록 오탐 수정 (2026-09-29)
- 현상: https://www.ruliweb.com/ 50페이지 검사에서 의심 요소 14개(기법 14건). 기록 runs/20260929-094057 확인 결과 14건 모두 같은 요소
  `div.target_list.time.screen_out > div.inner_box.row > ul.list.tab_box_page.dot:nth-of-type(3)` — 공통 레이아웃의 '베스트 뉴스' 비활성 탭 3쪽(display:none)이 14개 페이지에서 반복 검출.
- 원인(기록·코드로 확인):
  1) 분석 단위: 뉴스 10건(li, 각자 다른 기사 링크)을 가진 ul 전체를 하나의 문구로 판단. 4번째 뉴스의 '현금배당'(보조 주제어 배당), 8번째의 '포상 휴가 지급'(유도 표현), 9번째의 'SWC2026'을 합쳐 광고 기준 충족.
  2) 연락 수단: 가입코드용 규칙 `[A-Z]{3,}[0-9]{1,4}`가 '코드' 문맥 없이 연락·접속 수단으로 계산되어 대회명 SWC2026이 근거가 됨.
  3) 숨김 판정(display:none) 자체는 사실과 맞음(비활성 탭). 숨김은 이 건의 광고 판단을 올리지 않았지만, 짧은 문구는 숨겨져 있기만 해도 기준을 낮추는 규칙이 있었음(재현 페이지에서 '첫충 30%' 조각 오탐의 원인).
- 변경:
  - 콘텐츠 경계: 자식이 독립 항목(li·tr·article·dt·dd·option 2개 이상, 서로 다른 링크를 가진 블록 2개 이상, 같은 태그·클래스 반복 블록 2개 이상)인 요소는 합친 문구로 판단하지 않음. 항목은 각각 판단.

  - 근거 종류 분리: 연락·접속 수단(URL·도메인·전화번호·@아이디·메신저 아이디, 메일 주소 제외)과 가입·추천 코드('코드' 문맥 필수)를 구분. 영문+숫자만으로는 근거 아님. 화면 이유 문장도 '가입·추천 코드(…)'로 구분 표시.

## 남은 문제 / 다음 단계
- 탐지기와 테스트 사이트를 같은 사람이 만듦 → 일반화 근거 아님. 문구·구조가 다른 eval 사이트 필요.

- 실제 공공기관 사이트에서의 처리 시간은 미측정(디시인사이드만 측정). 분석 스레드 분리 후 동시 실행 효과 재측정 필요.
- 숨겨진 메뉴·목록 안의 주제어 단어(예: 디시인사이드 갤러리 이름 '드라마 카지노') 오탐은 이번 콘텐츠 경계 규칙으로 해소될 것으로 추정(해당 페이지 재검사는 하지 않음).
