## 이미지 속 글자 검사(OCR) — 진입 페이지만 (2026-09-29, 브랜치 feature/image-ocr)
- 선택 기능, 기본 꺼짐. 화면 '검사 설정'의 체크박스 또는 CLI `--ocr`.
- 엔진: Windows.Media.Ocr(Windows 10/11 내장, pywinrt 호출). 선택 이유: 모델 파일 없음(실행 중 다운로드 없음), 한국어·영문 한 인식기,
  CPU에서 이미지당 약 0.02초, PC 밖으로 데이터 전송 없음, 라이선스 부담 없음. 비교: RapidOCR(ONNX)는 한국어 모델 별도 준비와 Python 3.13용 패키지 구버전,
  Tesseract는 실행 파일·언어 데이터 별도 설치와 낮은 한국어 정확도. 단점: Windows 전용, 한국어 OCR 구성 요소 필요(한국어 Windows는 기본 포함).
- 흐름: 진입 페이지 img 수집(가장 큰 srcset 후보 > currentSrc > src, 지연 로딩 속성 대체) → 페이지 밖 요청으로 해당 이미지만 내려받기(브라우저 이미지 차단 유지, 외부 CDN 허용)
  → 준비(첫 프레임, 투명 배경 흰색, 긴 변 2400px 초과 축소/700px 미만 2배 확대, 명암 보정) → OCR → 줄·블록 구분 → 블록별 광고성 판단 → 화면·기록.
- 판정: 한 블록만으로 기준 충족 = 광고 의심, 블록을 합쳐야 충족하거나 주제어만 있으면 = 불확실. 이미지끼리 합치지 않음. OCR 출력으로 JAMO/HOMOGLYPH 판정하지 않음. img의 화면 숨김 여부는 따로 기록.
- 기록: scan.json의 images(이미지별 상태·사유·OCR 블록·판정·처리 시간·미리보기)와 ocr(엔진·OS 버전·한도·시간). 미리보기는 runs/<id>/images/에 저장해 화면에서 재요청 없이 표시.
- result_extra.json: 모집요강(붙임1·3·4)이 추가 탐지 파일을 허용함을 확인하고 구현. '광고 의심'만, technique "ETC", extra_finding "IMAGE_TEXT_AD(이미지 속 광고 의심 문구)". OCR이 실행된 경우에만 생성. result.json은 변경 없음.
- 같은 이미지 내용은 OCR 결과 재사용(sha1), 위치는 요소마다 보존. 이미지 속 링크는 방문하지 않음.
